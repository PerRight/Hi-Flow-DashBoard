## 0. 확정 사항 / 미확정 사항

**확정 (사용자, 2026-08-25)**
- 레이아웃 골격은 `대시보드 예시.png` 를 따른다 (좌측 레일 · 중앙 히트맵 · 우측 수심/센서/GPS).

- **헤더 바는 `#96D0FF` 유지** — `대시보드 예시.png` 와 동일. 헤더만 파랑, 본문은 무채색 회색.

  없앤다 — 같은 선택을 두 곳에서 하면 어긋난다. §3.10·§4·§4.1 참조.
- **GPS 패널 베이스맵은 위성사진** (2026-08-25 추가). VWorld Satellite 타일. §3.11 참조.
- **3D 히트맵은 `수중드론캡스톤클로드/visualize_heatmap.py` 형식을 채택한다** (2026-08-25 추가).
  깊이별 평면 슬라이스가 아니라 **(X, Y, 수심) 3차원 산점** — 세 수심층을 한 화면에 쌓아 보여준다.
  ⚠️ 이 변경은 `CLAUDE.md` 1절의 히트맵 팔레트를 바꾼다 — §2.4·§3.10의 "확인 필요" 참조.
- **수심 게이지·센서 게이지는 기존 대시보드 디자인을 그대로 채택한다** (2026-08-25 추가).
  `dashboard/src/panels/depth.js` 의 수직 물기둥 게이지와 `panels/gauges.js` 의 240° 아크 게이지를
  형태 그대로 쓰고, **색만 라이트 테마로 치환**한다. 새로 그리지 말고 기존 SVG 계산을 옮겨 쓸 것.

**미확정 — 답을 주시면 문서에 반영합니다 (§9에 재정리)**
1. 시계열 차트(Chart.js, 1초)가 예시 레이아웃에 없다. 센서 카드 안 스파크라인 / 별도 탭 / 삭제 중 무엇인가?
2. 윈치 조작 버튼(내림·정지·올림·auto)의 위치 — 수심 카드 내부로 가정했다.

### 2.4 색 — 3D 히트맵 (⚠️ 확인 필요 — CLAUDE.md 1절과 다름)

`수중드론캡스톤클로드/visualize_heatmap.py` 의 **파랑 단일 순차 램프**를 가져왔다.

```
정상 램프 13단계 (BLUE_RAMP):
#cde2fb #b7d3f6 #9ec5f4 #86b6ef #6da7ec #5598e7 #3987e5
#2a78d6 #256abf #1c5cab #184f95 #104281 #0d366b
주의(도메인 초과): #B26A00 + ◆ 다이아몬드
위험:              #C62828 + ◆ 다이아몬드
컬러 도메인: EC [100, 280] 고정 / TDS [50, 140] 고정  ← 그대로 유지
```

**바뀐 것과 안 바뀐 것**

| | 이전 (CLAUDE.md 1절) | 지금 |
|---|---|---|
| 정상 램프 | RdYlGn 6단계(초록→노랑→주황) | 파랑 13단계 단일 색상 |
| 초과 표시 | 짙은 자주 `#7B1F7A` (색만) | 주황/빨강 **다이아몬드**(색 + 형태) |
| 컬러 도메인 | EC [100,280] / TDS [50,140] | **동일 — 손대지 않음** |
| 임계값 | 280 / 700 · 140 / 350 | **동일 — 손대지 않음** |

왜 파랑 단일 램프인가:

1. 값의 크기를 읽는 데는 **단일 색상 순차 램프가 다색 램프보다 정확하다.** RdYlGn 은 중간
   노란 구간에서 순서가 흐려진다.
2. 이상 셀을 **형태(다이아몬드)로 구분**하므로 램프 자체에 경고색(주황·빨강)을 섞을 이유가 없어졌다.
   오히려 정상 셀의 주황과 초과 셀의 주황이 겹쳐 보이던 문제가 사라진다.
3. "색만으로 상태를 구분하지 않는다"(§7)를 히트맵에서도 지키게 된다.
4. 브랜드 `#96D0FF` 와 같은 계열이라 화면 전체가 한 벌로 읽힌다.

> **확인 필요**: 이 팔레트를 확정하면 `CLAUDE.md` 1절의 "히트맵 컬러 도메인 …초과는 전용 경고색
> (짙은 자주)" 문장과 `dashboard/src/config.js` 의 `HEATMAP_PALETTE` / `HEATMAP_OVER_COLOR` 를
> 함께 고쳐야 한다. **임계값과 컬러 도메인은 그대로**이므로 데이터 판정은 바뀌지 않는다.
> 승인해 주시면 두 파일을 수정하겠습니다 (CLAUDE.md 2절: 값 변경은 사용자 확인 후).

## 3. 컴포넌트 목록 (Figma 컴포넌트 + Variant)

### 3.1 `Header / AppHeader`
- 좌: 타이틀 `수중드론 수질측정 대시보드` + 부제 `세종 용암저수지` (Caption, `text/dim`)
- 우: `측정 차수` 라벨 → `SurveySelect` → `LinkStatus` → `Clock`(HH:MM:SS, tabular)
- Auto layout: 가로, space-between, 패딩 `0 24`, 높이 64 고정.

### 3.2 `Control / SurveySelect`
- 표기: `5차 (측정 중 138,302건)` — **숫자는 3자리 콤마**.
- Variant: `state = 측정중 | 완료 | 로딩 | 비어있음`
  - `측정중`: 차수 앞에 `color/state/ok` 점 표시
  - `비어있음`: `조사 기록 없음` (dim, 드롭다운 비활성)
- 폭 고정 240 px, 텍스트 넘치면 말줄임.

### 3.3 `Control / LinkStatus` (연결 상태 pill)
| Variant | 라벨 | 색 | 동작 |
|---|---|---|---|
| `ok` | `● 연결됨` | ok / ok-bg | — |
| `stale` | `● 연결 끊김 · 12초` | danger / danger-bg | 1초 주기 깜박임 |
| `reconnecting` | `● 재연결 중…` | caution / caution-bg | 점 회전 |

> **`stale`은 절대 조용히 넘어가면 안 된다** (`CLAUDE.md` 6절: 오래된 데이터를 정상처럼 보여주는 것이 최악의 버그).
> pill 변화 + 패널 전체 회색 처리 + 마지막 수신 경과 초를 동시에 보여준다.

### 3.4 `Layout / Panel` (모든 패널의 베이스)
- 구조: 제목 띠(높이 38, `surface/sunken`, 하단 1px border) + 본문(패딩 16)
- Variant: `state = normal | stale | empty | loading | error`
  - `stale`: 본문 전체 opacity 0.45 + 회색 필터, 우상단에 `연결 끊김` 배지 고정
  - `empty`: 중앙에 안내문 1줄 (예: `측정 레코드 없음 — HOLD 구간에서 생성됩니다`)
- 제목 우측에 옵션 슬롯(탭·범례·버튼) 하나.

### 3.5 `Control / SegmentTab`
- 사용처: EC/TDS 지표 전환, 0.5 / 1 / 1.5 m 깊이 전환
- Variant: `selected = true|false`, `disabled = true|false`, `hover`
- `selected`: 배경 `brand/100`, 테두리 `brand/500` 1px, 텍스트 `brand/700`, 좌측 3px 인디케이터
- 최소 높이 44 px — **보트 위에서 장갑 낀 손으로 누른다**. 터치 타깃 44×44 미만 금지.

### 3.6 `Control / Button`
- `primary`(CSV 내보내기) / `secondary` / `danger`
- Variant: `default | hover | pressed | loading | disabled`
- `loading`: 라벨 `내보내는 중…` + 스피너, 중복 클릭 차단

### 3.7 `Data / Gauge` (수온 · EC · TDS) — **기존 디자인 채택**

원본: `dashboard/src/panels/gauges.js`. 아래가 뚫린 **240° 아크 게이지 + 바늘**. 3열 그리드, 순서는
**수온 → EC → TDS**(원본과 동일). 패널 제목도 원본대로 `센서 실측값 / 1초 갱신`.

**형태 (원본 그대로 — 수치 변경 금지)**

```
viewBox 0 0 100 78 · 반지름 R=42 · 중심 (50,50)
시작각 START=150° · 스윕 SWEEP=240° · 아크 두께 7
바늘: 중심에서 R-15 지점부터 R 까지, 두께 3, 끝 둥글게 + 중심 원 r=3.5
```

### 3.8 `Data / DepthIndicator` — **기존 디자인 채택**

**좌측 물기둥 (원본 좌표 그대로)**

```
viewBox 0 0 96 252 · 기둥 x=26 w=30 y=28 h=210 rx=4
눈금 y = 28 + (depth / 1.5) × 210   → 0.5 / 1.0 / 1.5 m 점선 + 라벨
프로브: 16×14 rx=3 사각형, 기둥 중앙(x=41)을 따라 이동 + 수면부터 이어지는 세로선
`수면` 라벨 y=14 (기둥 위)
```

> **기둥 상단 여백 28 px 는 필수다.** 원본은 기둥이 y=14 에서 시작해 수심 0 m 일 때 프로브
> (중심 기준 위로 7 px)가 `수면` 라벨을 덮었다. 라벨과 프로브가 겹치면 "지금 수면에 있다"는
> 가장 기본적인 상태가 안 읽힌다. 상단에 프로브 반높이(7) + 라벨 높이(9) 이상을 비워 둔다.

**하강 · 상승 속도 (CLAUDE.md 1절 확정값 — 임의로 바꾸지 말 것)**

```
DESCENT_RATE = 0.5 / 30 m/s   →  0.5 m 내려가는 데 30초
ASCENT_RATE  = TBD (실측 전까지 하강과 동일하게 둔다)
HOLD         = 각 수심에서 30초
```

- 전체 1회 순환(0.5→1.0→1.5→수면)은 **약 4분 30초**다. 프로토타입·프리뷰도 이 속도를 지킨다 —
  빨리 감아 보여주면 "하강 진행 바가 거의 안 움직인다"는 실제 체감을 놓친다.
- 화면 갱신은 1초지만 프로브 이동은 0.2초 간격으로 그려 **끊겨 보이지 않게** 한다(속도는 동일).
  값 텍스트(`0.26`)는 1초 갱신 그대로 둔다 — 소수 둘째 자리가 0.2초마다 떨리면 읽을 수 없다.

**우측 정보 열 (원본 구성 유지)**

1. 대표 수치 `1.00` (44/800, tabular) + `m`
2. 보조문 — 상태에 따라 문구가 바뀐다 (원본 로직 그대로)

   - DESCENDING: `목표 수심 1.0 m` · ASCENDING: `수면 복귀 중` · SURFACE: `자동 순환 대기`

- `stale`: 패널 전체 opacity 0.5 + grayscale (원본 `setStale` 과 동일). 표시 중인 수심이 실제와
  다를 수 있기 때문이다.

### 4.1 UI 상태 소유권 (연동 규칙)

화면 상태는 딱 두 개고, 둘 다 **좌측 레일이 소유**한다. React로는 Context 하나에 두면 된다
(CLAUDE.md 3절 — Redux 도입하지 않는다).

| 상태 | 값 | 소유 | 이 상태를 따라 바뀌는 것 |
|---|---|---|---|
| `selectedMetric` | `ec` \| `tds` | 레일 카드 1 | 히트맵 셀 색·범례 도메인·제목, 센서 카드 해당 게이지 강조, 히트맵 툴팁 단위 |
| `selectedDepth` | `all` \| `0.5` \| `1.0` \| `1.5` | 레일 카드 2 | 히트맵에서 **강조할 층**(나머지 층은 0.16으로 남는다), 지도 측정 핀 필터, 히트맵 제목 보조문 |

- 깊이 탭은 3D 전환 이후 **필터가 아니라 강조**다. `전체 (3층)` 탭이 기본 후보이고, 특정 깊이를
  고르면 그 층만 진하게 남는다. 지도의 측정 핀에는 **필터로** 계속 작용한다(지도는 2D라 겹칠 수 없다).
- 지표를 바꾸면 **컬러 도메인이 함께 바뀐다**: EC `[100,280]` → TDS `[50,140]`,
  위험 표기도 `>700` → `>350` (CLAUDE.md 1절). 범례 숫자를 하드코딩하지 말 것.
- 지표 전환은 **표시 전환일 뿐 재측정이 아니다.** 이미 받은 레코드를 다시 칠할 뿐, 서버 재요청 없음.
- 센서 카드에서는 현재 지표 게이지를 `brand/500` 2px 아웃라인으로 강조한다(값은 셋 다 계속 보여준다 —
  수온까지 항상 보이는 편이 이상 진단에 유리하다).
- 지표·깊이 선택은 **CSV 내보내기 범위에 영향을 주지 않는다.** 내보내기는 항상 현재 차수 전체다.
  (혼동을 막기 위해 버튼 아래 Caption에 명시.)

## 5A. 기능 명세 (인터랙션)

> 이 절은 "무엇을 누르면 무엇이 바뀌는가"만 다룬다. `design/ui-wireframe.html` 이 이 절을
> 그대로 구현한 동작 프로토타입이다(윈치·차수·깊이 전부 실제로 눌러볼 수 있다. 목업은 10배속).

### 5A.1 측정 차수 (`Control / SurveySelect`)

`survey` 는 조사 시작 시 **라즈베리파이가 부여하는 정수**다 (CLAUDE.md 1절). 대시보드는 고르기만 한다.

| 항목 | 내용 |
|---|---|
| 목록 소스 | REST `GET /surveys` → `[{survey, started_at, ended_at, count}]` |
| 표기 | `5차 (측정 중 138,302건)` / `4차 (완료 96,410건)` — 숫자 3자리 콤마 |
| 진행 중 | **최대 1개.** `ended_at === null` 인 차수. 앞에 ok 점을 찍는다 |
| 기본 선택 | 진행 중 차수 → 없으면 가장 최근 완료 차수 |
| 갱신 | 진행 중 차수의 건수는 3초 배치로 증가 |

**차수를 바꾸면 바뀌는 것 / 바뀌지 않는 것 — 이 구분이 이 화면에서 가장 헷갈리는 지점이다.**

| 바뀐다 (측정 레코드 기반) | 바뀌지 않는다 (live 기반) |
|---|---|
| 히트맵 격자 | 센서 게이지 3개 |
| 깊이 탭 3개의 건수 | 현재 수심·상태 배지·진행 바 |
| 지도의 측정 핀·궤적 | 지도의 현재 보트 위치 마커 |
| CSV/XLSX 내보내기 대상 | 헤더 연결 상태 pill |

> `live` 는 "지금 센서가 뭘 보고 있나"이고 차수와 무관하게 계속 흐른다. 과거 차수를 보는 중에도
> 게이지는 현재값이다. 과거 차수 조회 중임을 잊지 않도록 **완료 차수를 고르면 수심 카드에
> `3차는 완료된 조사 — 조회 전용` 배지**를 띄우고 윈치 버튼을 전부 비활성화한다.

**엣지 케이스**

- 목록 비어있음 → `조사 기록 없음`, 셀렉트 비활성, 히트맵·지도 empty, 게이지는 정상 동작
- 목록 로딩 중 → `불러오는 중…`, 셀렉트 비활성
- 요청 실패 → `차수 목록을 불러오지 못했습니다` + `다시 시도` 링크. **빈 목록으로 위장하지 않는다**
- 조회 중이던 차수가 사라짐(삭제) → 진행 중 차수로 되돌리고 토스트 1회

### 5A.2 깊이 슬라이스 (0.5 / 1.0 / 1.5 m)

| 항목 | 내용 |
|---|---|
| 탭 라벨 | `0.5 m` + 우측에 현재 차수의 해당 깊이 레코드 수 |
| 클릭 시 | 히트맵 격자 교체 · 지도 측정 핀 필터 · 히트맵 제목 보조문 `1.0 m · 398건` |
| 데이터 | **클라이언트 필터다.** 이미 받은 레코드를 걸러낼 뿐 서버 재요청 없음 |
| 0건 | 탭을 흐리게(건수 stale색) + 히트맵 `이 깊이에서 측정된 레코드 없음 — HOLD 구간에서 생성됩니다` |
| live 영향 | **없음.** 게이지·수심·현재 위치는 깊이 선택과 무관 |

- 깊이는 `0.5 | 1.0 | 1.5` **세 개로 고정**이다 (CLAUDE.md 1절). 탭을 데이터로 생성하지 말고
  세 개를 고정 배치하되, 레코드가 없는 깊이도 **탭은 남겨둔다** — 없는 게 아니라 아직 안 잰 것이다.
- 지표(EC/TDS)와 깊이는 **독립**이다. 지표를 바꿔도 깊이 선택은 유지된다.

### 5A.3 현재 수심 · 윈치 조작

**표시**는 `live` 의 `state` / `depth_est` 가 유일한 출처다. **조작**은 명령 송신뿐이고,
상태기계는 라즈베리파이가 소유한다 (CLAUDE.md 0절).

| 명령 | 버튼 | 서버에 보내는 것 | 화면 |
|---|---|---|---|
| `down` | `▼ 내림` | 하강 시작 | 다음 측정 수심을 목표로 진행 바 |
| `stop` | `■ 정지` | 정지(HOLD 진입) | 측정 진행 `12/30초` |
| `up` | `▲ 올림` | 상승 시작 | 수면까지 잔여 진행 바 |
| `auto` | `자동 순환` | 자동 순환 토글 | `0.5→1.0→1.5` 순차, 각 수심에서 30초 HOLD |

하강 속도는 **0.5 m / 30초**(`DESCENT_RATE = 0.5/30 m/s`, CLAUDE.md 1절). 1회 순환 약 4분 30초.

- **낙관적 갱신 금지.** 버튼을 눌러도 화면의 상태 배지는 바꾸지 않는다. 서버가 보낸 다음 `live`
  메시지의 `state` 가 바뀌어야 반영된다 — 실제 윈치와 화면이 어긋나는 것이 이 화면의 최악 시나리오다.
  누른 직후에는 버튼에 `전송됨` 표시만 잠깐 준다.
- 수동 버튼을 누르면 **자동 순환은 해제**된다(`수동 조작` 표기).
- HOLD인데 `depth_est` 가 측정 수심(0.5/1.0/1.5 ±0.05)이 아니면
  `측정 수심 아님 — 기록되지 않음` 을 띄운다. 이때 히트맵·CSV에 점이 늘면 버그다.
- **비활성 조건 3가지** — 하나라도 걸리면 버튼 전부 비활성 + 사유 배지
  1. 원격 접속 → `원격 접속 — 윈치 조작 불가`
  2. 완료된 차수 조회 중 → `N차는 완료된 조사 — 조회 전용`
  3. `stale`(2초 이상 미수신) → `연결 끊김 — 명령이 전달되지 않습니다`

**상태 전이 (라즈베리파이 소유, 화면은 되비추기만)**

```
SURFACE ──down/auto──> DESCENDING ──목표 도달──> HOLD(30초) ──auto──> 다음 수심 DESCENDING
   ^                                               │                      │
   └──────────── 수면 도달 ── ASCENDING <──────────┴── 마지막 수심 종료 ───┘
```

### 5A.4 GPS 장착 후 위성 전환 체크리스트

지금은 위치가 목업이고, GPS를 달면 §3.11 그대로 위성으로 간다. 그때 확인할 것:

1. `config.js` 의 `VWORLD_KEY` 채우기 → 코드 수정 없이 Satellite 전환 (`basemap.js` 구현 완료)
2. `lat`/`lon` 이 `null` 로 올 때(위성 미포착) → 마커 숨김 + `GPS 미수신` 배지. **0,0 으로 찍지 말 것**
3. 첫 fix 전까지 지도 중심은 `SITE`(36.5751, 127.2214) 고정
4. HDOP/위성 수를 받는다면 정확도 나쁠 때 마커에 반경 원 표시
5. 측정 레코드의 `lat`/`lon` 이 `null` 이면 히트맵 집계에서 제외 (CLAUDE.md 6절과 동일 취급)
